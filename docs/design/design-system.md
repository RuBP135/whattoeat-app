# What To Eat 视觉设计规范

> 状态：v1 设计基线（2026-09-27）  
> 适用范围：Android 与 iOS 的 Compose Multiplatform UI  
> 样式板：[What To Eat Style Board v1](assets/what-to-eat-style-board-v1.png)

## 1. 文档职责

本文档是 What To Eat UI 设计的事实来源。新增或修改 UI 前必须先阅读本文档。

- 用户在后续需求中明确提出的新设计决定优先于本文档。
- 设计方向发生变化时，应先更新本文档，再修改页面。
- 样式板用于表达视觉气质，不代表任何具体页面已经定稿。
- 原项目的旧配色与旧组件外观不构成新设计的限制。

## 2. 品牌定位

正式品牌名为 **What To Eat**，简称 **WTE**。

核心气质：柔和、温暖、有食欲、轻松，但仍然清晰、高效、适合长期使用。

风格定义：**柔和桃橙 × 轻复古印刷 × 食物生活感**。

参考风格来自日系周边店与复古杂志排版，但只吸收以下设计语言：

- 低对比度纹样背景；
- 暖白纸张式内容面板；
- 标签式标题；
- 双层细描边；
- 克制的错位硬投影；
- 英文小字、品牌水印与不完全对称的编辑排版。

不得复制参考品牌的名称、Logo、鹿、蝴蝶结、文案或业务内容。

## 3. 已确认的设计决定

- 以样式板第一版为视觉基线，不采用更硬朗、高对比度的第二版。
- 使用中等装饰强度：品牌页明显，内容页克制，工具页安静。
- 采用唯一的 WTE 桃橙品牌主题，不保留旧版蓝、黄、绿、粉、紫五套主题色切换。
- 外观设置改为三种显示模式：`跟随系统`、`浅色模式`、`深色模式`。
- 同步设计浅色模式与深色模式；`跟随系统`根据宿主系统当前外观自动选择二者。
- 新安装默认使用 `跟随系统`。项目仍处于开发初期内测阶段，旧版五色选项不做数据迁移；实现时可删除或停止读取旧设置键。
- 保持现有启动器图标原样；允许派生简化的小碗、筷子、勺子标识用于 App 内。
- 视觉对比度可以柔和，但信息对比度与交互可辨识度不得降低。
- 功能、页面和导航按实际迭代逐步补充，不在当前阶段一次性固化完整产品结构。

## 4. 色彩系统

以下是 v1 基础色，正式实现前仍需结合组件状态复核对比度：

| 角色               | 色值        | 用途               |
|------------------|-----------|------------------|
| WTE Orange       | `#F9732F` | 品牌强调、选中状态、核心操作背景 |
| Peach Background | `#FFD8C2` | 品牌区域与纹样背景        |
| Paper Cream      | `#FFF9F1` | 卡片、输入框、导航栏       |
| Apricot          | `#F7B555` | 评分、提示、标签与小面积装饰   |
| Coral            | `#FF7B6B` | 次级强调，不代替危险语义色    |
| Caramel Outline  | `#8B4E2B` | 描边、次要文字、图标       |
| Cocoa Ink        | `#32180F` | 主要文字、关键图标、深色轮廓   |
| Muted Peach      | `#D9A885` | 分隔、禁用与弱化状态       |

规则：

- 不使用纯黑作为常规文字，优先使用 Cocoa Ink。
- 品牌橙 `#F9732F` 配白字的对比度不足；普通按钮文字应使用 Cocoa Ink，或将按钮底色另行加深。
- 浅绿色只能作为健康、成功、可用等语义色，不得成为第二套品牌主题。
- 危险操作使用独立语义红色，不得与品牌橙混淆。
- 纹样和装饰必须比前景内容更弱，不得影响阅读。

## 5. 背景系统

### 品牌型背景

用于首页、随机抽取、启动或空状态：

- 桃色底与低对比度菱格纹；
- 可少量加入米粒、蒸汽、小碗、筷子或勺子图形；
- 允许使用低透明度 `WTE` 或 `WHAT TO EAT` 水印；
- 主内容放在暖白纸张式面板上。

### 混合型背景

用于搜索、食物详情和点评等内容页面：

- 顶部保留品牌纹样；
- 主内容区域切换为暖白或浅桃纯色；
- 可以用波浪边缘或轻量分隔线完成过渡。

### 工具型背景

用于设置、食物编辑和表格管理：

- 暖白纯色为主；
- 纹样只出现在标题区或空状态；
- 不在长列表每一项重复双边框与硬投影。

## 6. 字体与排版

- 品牌名固定写作 `What To Eat`，简称固定写作 `WTE`。
- 页面大标题可使用圆润、较粗的展示字体，并允许非常轻的错位阴影。
- 随机结果是展示型文字，应成为页面最明显的信息。
- 正文、点评、表单和长列表使用清晰的系统中文字体。
- 英文辅助文字可使用全大写和适度字间距，但不得牺牲阅读速度。
- 不得在正文中使用装饰字体、文字描边或投影。
- 引入自定义字体前必须确认跨端加载方式、授权许可和资源体积，并明确告知用户。

## 7. 形状、描边与投影

- 视觉以柔和的小到中等圆角为主，避免所有元素都变成胶囊形。
- 核心卡片可以使用双层细描边；普通卡片使用单层轻描边或色面分层。
- 错位硬投影只用于主按钮、核心结果卡和少数标题标签。
- 投影颜色应降低饱和度与不透明度，偏移距离保持克制。
- 按钮按下时可以轻微向投影方向位移，形成实体按键反馈。
- 工具页与密集列表优先使用留白和分隔线，不堆叠装饰。

## 8. 间距与自适应

- 使用 `4.dp` 基础网格，常用间距为 `8/12/16/24/32.dp`。
- 页面水平边距应随屏幕宽度自适应，避免以固定宽度作为主要布局策略。
- 交互目标通常不得小于 `48.dp`。
- Android 与 iOS 需要保持同一品牌语言，同时正确处理安全区域、状态栏和底部手势区域。
- 手机是首要布局，但不得写死导致横屏或平板不可用。

## 9. 组件原则

- 保留 Material 3 的交互、状态、可访问性与语义结构，再覆盖 WTE 的颜色、形状和排版。
- 主按钮、次按钮、文本按钮、危险按钮必须有明确层级。
- 卡片应突出真实食物图片、名称、评分、标签与位置，不让装饰压过内容。
- 标签仅表达分类、状态或筛选，不把普通按钮伪装成标签。
- 底部导航使用暖白表面、焦糖线条与橙色选中状态；装饰边缘只能轻量使用。
- 加载、空状态、错误、禁用、按下、聚焦和选中状态都必须纳入设计。

## 10. 深色模式

- 外观设置只控制显示模式，不改变 WTE 的品牌色体系。
- `跟随系统`、`浅色模式`、`深色模式`必须使用同一套语义化主题令牌。
- 深色模式采用深巧克力背景，而不是纯黑或对浅色模式机械反色。
- 主要文字使用暖白，品牌强调仍使用橙色与杏黄色。
- 菱格纹保持低对比度，只作为背景肌理。
- 卡片依靠不同层级的巧克力色表面区分，避免大面积发光描边。
- 浅色与深色模式必须表达同一品牌，不应像两套独立主题。

## 11. 图标与装饰图形

- 启动器图标保持现有的橙色饭碗、米饭、筷子、蒸汽和勺子构图。
- App 内可使用简化的小碗标识，不应反复缩放完整方形图标。
- 装饰图形以饭粒、蒸汽、小碗、餐具和简单星形为主。
- 不混用轮廓粗细差异明显的图标风格。
- 装饰图形不能替代有明确语义的功能图标。

## 12. 动效

- 随机抽取的约 2 秒动画是品牌级动效，应成为重点。
- 普通按压、选择和切换动画保持短促，通常为 `150–300ms`。
- 背景不持续运动，避免干扰阅读与增加耗电。
- 动效不能阻塞操作，并应考虑减少动态效果的用户偏好。

## 13. 禁止方向

- 不回退到默认 Material 3 组件直接拼装的视觉效果。
- 不恢复蓝、黄、绿、粉、紫五套独立品牌主题。
- 不把显示模式重新设计成可自由更换品牌主色的主题选择器。
- 不全局铺满食物照片或高对比度纹样。
- 不把所有卡片、按钮和输入框都做成高装饰双边框。
- 不为了柔和而降低正文、按钮文字和选中状态的可读性。
- 不复制参考网页的品牌资产和具体页面布局。

## 14. 后续工作流程

1. 每次只确定当前迭代所需的功能、页面与导航，不提前虚构后续产品细节。
2. 先根据本文档完成当前页面的设计讨论与线框。
3. 明确页面内容、状态和交互后，生成必要的高保真参考图。
4. 用户确认页面方案后，才修改 Compose UI。
5. 新增依赖、字体或资源前必须明确告知用户。
6. UI 与业务逻辑均保持在 `commonMain`，不得引入 `android.*` 或 `java.*`。
7. 每次实现检查跟随系统、浅色、深色、Android、iOS 和不同屏幕宽度。
